# LeKiwi → 520 编码电机底盘：驱动板选型与接线方案

> 场景：把 LeKiwi 的原装 3 轮全向底盘换成 520 直流编码电机底盘（草地上跑）。
> 问题：要配什么驱动板？LeKiwi 原来那块板还能用吗？

---

## 一、先回答：原来那块板**不能用**

LeKiwi 原装的是 **Feetech 总线舵机驱动板**（Waveshare Bus Servo Adapter 类），它和 520 电机在电气、协议、功率三个层面都对不上：

| 维度 | 原板（Feetech 总线舵机板） | 520 直流编码电机需要 |
|---|---|---|
| 输出信号 | 串行总线数据包（TTL 半双工，给 STS3215 发位置/速度指令） | **PWM + 方向电平**（或 PWM×2 正反转） |
| 功率级 | 板载无 H 桥，本质是 USB↔串口转换 + 总线收发 | **需要 H 桥大电流输出**（堵转 3A/路） |
| 编码器 | 无编码器输入（舵机编码器在舵机内部，走总线读） | **需要 AB 相正交解码输入** |
| 电流能力 | 单总线约 2A 量级 | 双电机启动峰值 6A+ |
| 电压域 | 12V 供电但只为舵机 | 12V 直驱电机，独立大电流回路 |

**结论：必须新增一套电机驱动，不是替换。** 原来那块板继续留着给机械臂的 6 个 STS3215 用（ID 1–6），底盘走另一条链路——两条链路并行，互不干扰。

## 二、520 电机实际参数（先算账再选板）

市面 520 编码电机（JGB37-520 / MD520 系列）主流规格：

| 参数 | 1:19 | 1:30 | 1:56 |
|---|---|---|---|
| 输出转速 | 550 rpm | 333 rpm | 205 rpm |
| 额定扭矩 | 2.2 kg·cm | 3.3 kg·cm | 6.5 kg·cm |
| 堵转扭矩 | 3.1 kg·cm | 4.8 kg·cm | 8.3 kg·cm |
| 额定电流 | 0.3 A | 0.3 A | 0.3 A |
| **堵转电流** | **3 A** | **3 A** | **4 A** |
| 编码器 | AB 相增量霍尔，**11 PPR**，供电 3.3–5V，内置上拉整形 | | |
| 每转计数 | 减速比 × 11 × 4（四倍频）：1:30 → **1320 counts/rev** | | |

### 选型规则

> **驱动板持续电流 ≥ 电机堵转电流 × 1.5**
> → 3A × 1.5 = **至少 4.5A 持续**

这条规则是硬门槛，不是建议。520 电机标称只跑 0.3A，但启动瞬间、卡草、顶墙时会直接拉满堵转电流并持续数秒。

## 三、驱动板选型

| 方案 | 持续/峰值电流 | 结论 | 说明 |
|---|---|---|---|
| **L298N** | 2A / 3A | ❌ **禁用** | 压降 1.4V+、发热巨大，520 直接烧 |
| **TB6612FNG** | 1.2A / 3.2A | ❌ **禁用** | 社区有实测：驱动 520 编码电机**一分钟冒烟烧毁**（堵转 3.5A 远超峰值余量） |
| **DRV8871** | 3.6A / 6A | ⚠️ 勉强 | 单路、6.5–45V、无独立逻辑电源。3.6A 对 3A 堵转余量不足，但有内部限流保护，可用 |
| **BTS7960 / IBT-2 模块** | 43A 硅极限，模块实际 ~15A | ✅ **推荐** | 3.3V 逻辑兼容、便宜、散热好。**一个 IBT-2 模块 = 一个完整 H 桥 = 驱动 1 个电机** |
| **Cytron MDD10A** | 10A×2 双路 | ✅ 省事 | 双路集成、树莓派有现成 Python 库，贵（¥180+） |
| **ZK-BM16 等国产双路大功率** | 7–10A×2 | ✅ 性价比 | 双路集成少接线，品质参差需挑 |

### 推荐组合

**2 驱方案（推荐）**：`ESP32 + 2× IBT-2(BTS7960)` ≈ ¥70–90
**4 驱方案**：`ESP32 + 4× IBT-2(BTS7960)` ≈ ¥110–150

> **为什么建议 2 驱而不是 4 驱**：4 个 520 同时堵转 = 12A 峰值，已经逼近 LeKiwi 那块 12V 4500mAh 电池（约 3C / 13.5A）的天花板；而且 4 驱 skid steer 原地转向会把草皮犁出坑。同侧各驱动 1 个、另外 2 个换成被动轮（或拆掉电机只留轮），扭矩够、电够、草皮也保得住。

## 四、推荐架构

```
┌─────────────────────────── 树莓派 5 ───────────────────────────┐
│                                                                │
│   /dev/ttyACM0 ──► 原 Feetech 总线板 ──► 6× STS3215 (臂 ID1-6) │
│                                                                │
│   /dev/ttyUSB0 ──► ESP32 (电机协处理器)                         │
│                      │                                         │
│                      ├─ LEDC PWM 20kHz ──► IBT-2 #1 ──► 左电机 │
│                      ├─ LEDC PWM 20kHz ──► IBT-2 #2 ──► 右电机 │
│                      └─ PCNT 硬件正交解码 ◄── 编码器 A/B ×2     │
└────────────────────────────────────────────────────────────────┘
```

### 为什么中间要插一个 ESP32（而不是树莓派直驱）

1. **树莓派没有硬件正交解码器**。AB 相只能靠软件中断读，30Hz 控制环下低速抖动严重、CPU 占用高；ESP32 有 **PCNT 硬件计数单元**，4 路正交解码零 CPU 开销。
2. **软件 PWM 抖动**。Linux 不是实时系统，PWM 会出现毫秒级抖动，电机啸叫、低速爬行。ESP32 的 LEDC 是硬件 PWM。
3. **闭环要跑 100Hz**，跑在 MCU 上才稳。树莓派专心做视觉/语音/网络。
4. 这也是 XLeRobot 无刷版走 ODrive、商用底盘走 MCU 协处理器的同一个思路。

## 五、接线

### 5.1 520 电机 6 线（PH2.0-6P）

| 线色 | 功能 | 接到 |
|---|---|---|
| 红 | 电机 + | IBT-2 `B+`（或 `M+`） |
| 白 | 电机 − | IBT-2 `B-`（或 `M-`） |
| 蓝 | 编码器电源 | **ESP32 3V3**（见下方电平说明） |
| 黑 | 编码器 GND | ESP32 GND |
| 黄 | 编码器 A 相 | ESP32 GPIO（PCNT 输入） |
| 绿 | 编码器 B 相 | ESP32 GPIO（PCNT 输入） |

> ⚠️ **电平坑**：编码器供电 3.3–5V，**输出幅度 = 供电电压**。
> - 给 **3.3V** 供电 → 输出 3.3V，ESP32 可直连，**最省事，推荐**。
> - 若已接 5V → 输出 5V，**必须分压**（1kΩ 串 + 2kΩ 对地）或用电平转换芯片，否则打穿 GPIO。
> - 线色各批次不一致，接线前一定看电机壳上的丝印。

### 5.2 IBT-2 / BTS7960 模块

| 端子 | 接什么 |
|---|---|
| `VCC` | ESP32 5V（逻辑电源，**不要**接 3.3V，部分模块需 5V） |
| `GND` | 与 ESP32、电池负极**共地** |
| `RPWM` | ESP32 PWM（正转占空比） |
| `LPWM` | ESP32 PWM（反转占空比） |
| `R_EN` / `L_EN` | 接 5V（常使能）或接 GPIO 做急停 |
| `B+` / `B-` | 电机两根线 |
| `+` / `-`（大电流端） | **电池 12V 直供**，线径 ≥18AWG |

> 正转：`RPWM=PWM, LPWM=0`；反转：`RPWM=0, LPWM=PWM`；滑行停止：两者都 0。
> PWM 频率建议 **15–25kHz**（超音频，避免啸叫；太高开关损耗大）。

### 5.3 树莓派 ↔ ESP32

- **简单方案：USB**（ESP32 虚拟串口，`/dev/ttyUSB0` 或 `/dev/ttyACM0`）
  - 注意：树莓派 USB 总供电有限（约 1.2A），ESP32 峰值 500mA 可能拉低电压 → **ESP32 用独立 5V 供电，USB 只走数据**（或剪断 VBUS）
- **稳定方案：UART**（`GPIO14/TX → ESP32 RX`，`GPIO15/RX → ESP32 TX`，共地）
  - 树莓派要先 `dtoverlay=disable-bt` 释放 `/dev/ttyAMA0`（否则被蓝牙占）

## 六、电源与保护（最容易翻车的地方）

1. **电机电源与逻辑电源分开走线**，只在电池负极单点共地，避免电机启动压降把树莓派搞重启。
2. **加 1000µF 电解 + 0.1µF 陶瓷电容**跨在电池输出端，吸收启动冲击。
3. **加 10A 保险丝**（2 驱）/ 15A（4 驱）。
4. **电流核算**（12V 侧）：

   | 负载 | 稳态 | 峰值 |
   |---|---|---|
   | 2× 520 电机 | 0.6 A | 6 A（堵转） |
   | 6× STS3215 机械臂 | 1–2 A | 3–4 A |
   | 树莓派 5（经 DC-DC） | 1.5 A | 2 A |
   | **合计** | **~3–4 A** | **~11–12 A** |

   LeKiwi 原装 12V **4500mAh**（约 3C ≈ 13.5A）**够用但不宽裕**。若上 4 驱或频繁爬坡，建议换 12V 10Ah 或 4S 锂电（14.8V，520 额定 12V 可吃 11–16V）。

## 七、ESP32 固件接口（协议要定死）

保持和原来一样的语义，树莓派侧只发速度，不关心轮子：

```
树莓派 → ESP32 (115200 8N1, 一行一条)
  V <vx> <w>        线速度 m/s + 角速度 rad/s   ← 差速逆解在 ESP32 里算
  S                 立即停止
  P <kP> <kI>       调 PI 参数

ESP32 → 树莓派 (10Hz)
  E <l_ticks> <r_ticks> <vbat_mv> <err>
```

- ESP32 内部：`V` 指令 → 差速逆解 → 目标轮速（m/s）→ 编码器实测轮速 → **PI 闭环 100Hz** → PWM
- **看门狗**：500ms 没收到指令自动停车（草地跑远断连不至于失控）
- 差速逆解：`v_L = vx - w·W/2`，`v_R = vx + w·W/2`（W = 两驱动轮轮距）
- 轮速换算：`m/s → ticks/s = v / (π·D) × counts_per_rev`

## 八、软件侧接入（本项目改动点）

原代码 `pi_client/moyurobot/core/robot_service.py:131-137` 写死了 `LeKiwi` / `LeKiwiConfig`。改造成：

```
BASE_TYPE=omni3   → 原 LeKiwi（不动，随时可回退）
BASE_TYPE=diff2   → 新 DiffBaseLeKiwi：FeetechMotorsBus(6 臂) + SerialBaseTransport(ESP32)
```

`DiffBaseLeKiwi` 实现 lerobot 的 `Robot` 接口，`send_action()` 收到还是原来那个字典：

```python
{"x.vel": 0.2, "y.vel": 0.0, "theta.vel": 0.0, "arm_shoulder_pan.pos": 0, ...}
```

- `x.vel / theta.vel` → 打包成 `V` 帧发给 ESP32
- `y.vel` → **差速底盘无效**，丢弃（上层 UI 要同步改，见下）
- `arm_*.pos` → 原样走 FeetechMotorsBus

**上层要改的语义**（这一步容易漏，改完才发现 A/D 键没反应）：

| 位置 | 现状 | 差速后 |
|---|---|---|
| `web/static/mobile.html` | 屏幕左右 → `y.vel` 平移 | 改成原地转 或 弧线 |
| `web/static/script.js` | A/D 键平移 | 同上 |
| `mcp/server.py` `move_robot(left/right)` | 直接平移 | 降级为"转向 + 前进"组合 |
| `config/default.json` | `linear_speed: 0.2` | 照旧，但 `max` 建议 0.6（520 能跑更快） |

## 十、落地顺序建议

1. **先单电机台架验证**：ESP32 + 1 个 IBT-2 + 1 个 520 电机，跑通编码器计数方向和 PI 闭环（用串口打印实测 rpm）。这一步不对，后面全白费。
2. 双电机装车，验证差速直行不跑偏（左右编码器 counts 一致性）。
3. 接树莓派，跑 `BASE_TYPE=diff2`，先用 `S` 急停确认看门狗生效。
4. 再改上层 UI 的平移语义。
5. 最后调机械臂与底盘的时序（底盘运动和臂动作同时下发会不会互相阻塞）。
